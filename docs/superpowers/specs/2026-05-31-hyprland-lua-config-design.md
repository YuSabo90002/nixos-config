# Hyprland WM 設定の Lua 化 設計

- 日付: 2026-05-31
- 対象: `modules/home/hyprland.nix` の `wayland.windowManager.hyprland` 設定
- 関連メモ: `hyprland-configtype-lua.md`（本設計で「保留」を解除し実施へ）

## 背景・動機

home-manager 26.05+ で `wayland.windowManager.hyprland.configType` のデフォルトが
`hyprlang` → `lua` に変わった。現在は `configType = "hyprlang"` を明示して従来形式を維持している。

調査の結果、過去メモの前提（「対応 Hyprland 要実機確認」「extraConfig の書き直しが難所」）は
更新が必要だった:

- `pkgs.unstable.hyprland` は **0.55.2** で Lua 設定をフル対応。
  `share/hypr/hyprland.lua`（公式サンプル）と `share/hypr/stubs/hl.meta.lua`（`hl.*` API スタブ）を同梱。
- Lua モードは単なるエスケープ書き換えではなく、**設定モデルが `hl.*` API 呼び出しに変わる**
  （`hl.config({...})` / `hl.bind(...)` / `hl.window_rule({...})` / `hl.monitor({...})` 等）。

動機は「動作等価を最優先」とし、見た目・挙動を現行 hyprlang 設定と 1:1 で維持する。
（将来 hyprlang サポートが廃止される可能性への先回りも兼ねる。）

## スコープ

### 対象（Lua 化する）
- `modules/home/hyprland.nix` の `wayland.windowManager.hyprland.settings` + `extraConfig`
  （現行 23〜281 行）= ユーザーセッションの WM 設定のみ。

### 対象外（変更しない）
- **greeter の Hyprland**: `modules/nixos/desktop.nix` の
  `environment.etc."greetd/hyprland.conf".text`（生 hyprlang）。
  `Hyprland -c /etc/greetd/hyprland.conf` で起動するシステムレベル設定で、
  home-manager モジュールも `configType` も経由しない。**hyprlang のまま据え置き**。
- `programs.hyprlock` / `services.hypridle` / `services.hyprpaper`:
  Lua モードを持たない別プログラム。**hyprlang のまま据え置き**。
  （壁紙 split 生成・hyprlock の input-field/label 等はそのまま。）

## アーキテクチャ決定: ルート2「本物の Lua ファイルを直書き、Nix は配置のみ」

### 決定
リポジトリルートに `hypr/hyprland.lua` を本物の Lua として作成し、home-manager は
`xdg.configFile` で配置するだけにする（`ags/` を TypeScript で直書きするのと同形式）。

### 根拠（検討した代替案との比較）
- **却下: 純 settings（Nix attrset + `mkLuaInline` 断片）**
  - Lua が Nix 文字列内の式断片としてのみ存在 → 同梱スタブ + `.luarc.json` による
    LSP/型チェックが効かない。dispatcher 表現がエスケープ文字列になる。
- **却下: extraConfig に生 Lua をハードコード**
  - 巨大な Lua heredoc を Nix 文字列に埋める形。可読性が低い。
- **採用: ルート2（実 `.lua` ファイル + Nix で配置）**
  - リポジトリの確立済みルール「設定 DSL は Nix で生成（hyprlang/JSON/YAML）、
    プログラミング言語は直書き（AGS の TS）」に一致。Lua は PL なので直書き側。
  - 同梱スタブ (`hl.meta.lua`) + 自動生成 `.luarc.json` による LSP/補完/型チェックが効く
    （ルート1では得られない実利）。
  - この WM 設定は Nix 補間（store path 参照）を一切必要としない（壁紙パスは
    hyprpaper/hyprlock 側＝対象外）。エスケープ地獄を回避し、公式 wiki/サンプルからの
    コピペがそのまま動く。
  - 制約: 「外部 .lua を `settings` 経由で読む」関数は存在しない（`settings` は
    `hl.<name>(args)` / `local x=expr` しか出力できない設計）。`mkLuaInline` は値を
    生 Lua 式としてマークするだけでファイルローダーではない。

### 配置メカニズム: `extraConfig = builtins.readFile`（`xdg.configFile.source` ではなく）

実 `.lua` を取り込む口は2つあり、require 挙動は両者で同一（後述）。本設計は
`extraConfig = builtins.readFile ./hypr/hyprland.lua` を採用する。
- `extraConfig != ""` で module の `shouldGenerate=true` となり、module が
  `~/.config/hypr/hyprland.lua` を生成し **`onChange = reloadConfig`（hyprctl reload）を
  自動付与**する。`xdg.configFile.source` 方式では自前で onChange を書く必要があり、その手間が消える。
- 生成ファイルは `-- Generated by Home Manager` ヘッダ + `-- extraConfig` ラッパー + 取り込んだ Lua。
- LSP は引き続きリポジトリの実 `hypr/hyprland.lua` を編集する際に効く（module はテキストを埋め込むだけ）。

## ファイル配置（AGS ミラー）

- 新規: `hypr/hyprland.lua`（リポジトリルート、`ags/` と同階層）。
- 新規（任意）: `hypr/.luarc.json` — 編集時 LSP 用。
  `diagnostics.globals = ["hl"]` と、同梱スタブを `workspace.library` に指定。
  store path はバージョン更新でドリフトするため、効かなくなったら更新する運用。
- **両ファイルとも `git add` 必須**（flake のソース純度。未追跡だと
  `Could not resolve` になる既知の罠）。

## `modules/home/hyprland.nix` の変更

```nix
wayland.windowManager.hyprland = {
  enable = true;
  configType = "lua";
  package = pkgs.unstable.hyprland;
  systemd.enable = false;
  settings = { };               # 構造化設定は使わない（中身は hyprland.lua へ）
  extraConfig = builtins.readFile ../../hypr/hyprland.lua;
};
```

- `extraConfig != ""` なので module の `shouldGenerate=true` → module が
  `~/.config/hypr/hyprland.lua` を生成し（ヘッダ + 取り込んだ Lua）、
  **`onChange = reloadConfig`（hyprctl reload）を自動付与**する。reload を自前で書かなくてよい。
- `.luarc.json` は `configType=="lua" && finalPackage!=null` だけが条件なので
  引き続き `~/.config/hypr/.luarc.json` に自動生成される。
- パッケージ導入・`xdg.portal` 設定は引き続きモジュール任せ。

## `hyprland.lua` 翻訳マッピング（hyprlang → Lua `hl.*`）

| 現行 hyprlang | Lua |
|---|---|
| `monitor = "DP-1,2560x1440@60,0x0,1"` | `hl.monitor({ output="DP-1", mode="2560x1440@60", position="0x0", scale=1 })` |
| `general/decoration/dwindle/input/misc` | `hl.config({ general={...}, decoration={...}, dwindle={...}, input={...}, misc={...} })` |
| `col.active_border = "rgba(A6E22Eee) rgba(66D9EFee) 45deg"` | `general.col.active_border = { colors={"rgba(A6E22Eee)","rgba(66D9EFee)"}, angle=45 }` |
| `bezier = easeOutQuint, 0.23,1,0.32,1` | `hl.curve("easeOutQuint", { type="bezier", points={ {0.23,1},{0.32,1} } })` |
| `animation = windows,1,4,easeOutQuint,popin 80%` | `hl.animation({ leaf="windows", enabled=true, speed=4, bezier="easeOutQuint", style="popin 80%" })` |
| `device { name=...; sensitivity=...; }` | `hl.device({ name="...", sensitivity=0.8 })` |
| `workspace = "1, monitor:DP-1, default:true"` | `hl.workspace_rule({ workspace="1", monitor="DP-1", default=true })` |
| `bind = "$mod, Return, exec, $terminal"` | `hl.bind(mod.." + Return", hl.dsp.exec_cmd(terminal))` |
| `killactive` | `hl.dsp.window.close()` |
| `togglefloating` | `hl.dsp.window.float({ action="toggle" })` |
| `fullscreen` / `pseudo` / `pin` | `hl.dsp.window.fullscreen()` / `.pseudo()` / `.pin()` |
| `movefocus, l/r/u/d` | `hl.dsp.focus({ direction="left"/"right"/"up"/"down" })` |
| `workspace, N` / `workspace, m+1` / `e+1` | `hl.dsp.focus({ workspace=N / "m+1" / "e+1" })` |
| `movetoworkspace, N` | `hl.dsp.window.move({ workspace=N })` |
| `resizeactive, -30 0`（binde） | `hl.bind(..., hl.dsp.window.resize({ x=-30, y=0, relative=true }), { repeating=true })` |
| `swapwindow, l`（要確認） | `hl.dsp.window.swap({ direction="left" })`（引数形は実装時に stub/wiki で確定） |
| `layoutmsg, preselect d`（要確認） | `hl.dsp.layout("preselect d")`（実装時に確定） |
| `exit` | `hl.dsp.exit()` |
| `bindm = "$mod, mouse:272, movewindow"` | `hl.bind(mod.." + mouse:272", hl.dsp.window.drag(), { mouse=true })` |
| `exec-once = "discord"` 等 | `hl.on("hyprland.start", function() hl.exec_cmd("discord"); hl.exec_cmd("pear-desktop") end)` |
| `windowrule { name=...; match:class=...; float=true }` | `hl.window_rule({ name="...", match={ class="..." }, float=true })` |

- ワークスペース 1-10（switch 10 + move 10 = 20 bind）は Lua の `for i=1,10 do ... end` で生成。
- `mod="SUPER"` / `terminal="alacritty"` / `menu="ags request ..."` は Lua の `local` 変数。

## 実装時に最終確認が必要な点（stub / wiki）
1. `hl.dsp.window.swap` の引数形（`{direction=...}` か `"l"` か）。
2. `layoutmsg, preselect d/r` の Lua 表現（`hl.dsp.layout("preselect d")` で通るか）。
3. mouse bind のオプションキー（公式サンプルは `{ mouse = true }`。`BindOptions` 型には
   `mouse` が無く `drag`/`click` があるが、公式サンプルが `mouse=true` を使用＝許容される想定）。
4. `shadow.offset = "0 4"` 等、文字列で渡している値が Lua でも受理されるか。

## 将来の分割（`require`）と相対パスの扱い

Hyprland 公式（メンテナ vaxerski, Discussion #14396 + wiki）より:

- `require()` は **`$XDG_CONFIG_HOME/hypr`（= `~/.config/hypr`）を基点**に解決される。
  「呼び出し元の場所」でも「`hyprland.lua` の realpath」でもない。
  例: `require("modules.myThing")` → `~/.config/hypr/modules/myThing.lua`（区切りは `/` でも `.` でも可）。
- したがって `hyprland.lua` が **/nix/store への symlink でも require の基点は崩れない**
  （store の実体ディレクトリには行かない）。これが今回の懸念への回答 = **相対パスは崩壊しない**。
- config ディレクトリ外の絶対パスは `require` ではなく `loadfile("/abs/path")` を使う。
- 配置メカニズム（`extraConfig=readFile` か `xdg.configFile.source` か）は require 挙動に**影響しない**
  （どちらも `~/.config/hypr/hyprland.lua` が store symlink になり、require は XDG パスにアンカー）。

注意（崩壊ではなく配置漏れ）: require 先のサブモジュールは自動 deploy されない
（`readFile` はメインファイルのテキストを埋め込むだけ）。将来分割する場合は
リポジトリに `hypr/lua/` を切り、`xdg.configFile."hypr/lua".source = ../../hypr/lua;` で
サブディレクトリごと `~/.config/hypr/lua/` に配置し、`require("lua.foo")` とするのが推奨
（AGS のモジュール構成と同思想）。今回は単一ファイルなので分割は行わない。

## 検証計画
1. `nix flake check`（評価・型エラー無し）。
2. `nix run .#activate` で適用。
3. `hyprctl reload` または再ログイン後、`hyprctl configerrors` がエラー無しであること。
4. 実機目視: モニタ配置(DP-1/DP-2)、主要 bind（端末起動/ランチャー/ワークスペース 1-10/
   vim フォーカス・入替/リサイズ/スクショ/マウス移動）、window_rule（pavucontrol float、
   PiP pin、steam fullscreen、discord/youtube-music の WS10 振り分け）、autostart
   （discord / pear-desktop）、アニメーション・装飾。
5. 壁紙(hyprpaper)・ロック(hyprlock)・アイドル(hypridle) が従来どおり動くこと（対象外だが回帰確認）。

## ロールバック
- `git revert` で `hyprland.nix` を hyprlang 版に戻し、`hypr/` を削除して `nix run .#activate`。
